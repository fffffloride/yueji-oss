## 一、项目定位

- 本项目基于 youlai `vue3-element-admin` 模板（Vue 3 + Vite + TypeScript + Element Plus + Pinia）。
- 系统层页面（`src/views/system/*`：用户/角色/菜单/字典/配置/日志/通知）保留不动，作为后台权限底座。
- 业务页面全部新增，遵循模板既有分层规范：
  - API 层：`src/api/<域>/index.ts` + `src/api/<域>/types.ts`（参考 `src/api/system/user/`）
  - 页面层：`src/views/<域>/<页面>/index.vue`（参考 `src/views/system/user/index.vue`）
  - 菜单与路由：通过后台「菜单管理」动态配置，不手写静态路由
- 可复用的模板能力：`vxe-table`（复杂表格）、`@wangeditor-next`（富文本）、`exceljs`（导出）、`echarts`（报表）、`codegen`（基础 CRUD 生成）。

## 二、分阶段任务

### 阶段 0：环境连通（对齐总计划阶段 0）

- 确认 `.env.development` 指向本地 youlai-nest 后端（默认 `http://localhost:8000`），`pnpm dev` 启动、admin 登录成功
- 核对模板版本与后端接口兼容性（本模板含 tenant/app 等页面，后端若无对应接口，隐藏相关菜单即可，不删代码）
- 规划业务菜单结构（录入 sys_menu）：商品管理 / 订单管理 / 会员管理 / 营销管理 / 预约管理 / 分销管理 / 数据统计 / 页面管理

### 阶段 2：商品域页面

- `src/api/product/`：分类、SPU、SKU、标签接口封装
- `src/views/product/category/`：三级分类树管理（参考 `src/views/system/dept/` 的树形页面）
- `src/views/product/list/`：商品列表（查询/上下架/标签筛选）
- `src/views/product/edit/`：商品编辑（主图/轮播图上传用模板 file 接口、富文本详情用 wangeditor、多规格 SKU 表格编辑、购买权限设置）

### 阶段 3：订单域页面

- `src/api/order/`：订单查询、详情、核销、导出接口
- `src/views/order/list/`：订单列表（订单号/状态/时间/会员/核销人组合筛选）
- `src/views/order/detail/`：订单详情（商品、支付、核销信息、操作日志）
- 核销操作：核销确认/撤销、批量核销
- 订单导出 Excel（exceljs）

### 阶段 4：会员管理页面（P0 收尾）

- `src/api/member/`：会员查询、详情、标签、备注接口
- `src/views/member/index.vue`：会员列表（昵称/手机号、状态筛选）
- 同页抽屉式会员 360 视图（资料、订单统计、最近订单、标签、备注）

### 阶段 5：营销基础页面（已完成）

- `src/api/marketing/`：等级、积分规则/流水、优惠券模板/发放/记录接口与类型
- `src/views/member/level/`：等级分页、新增编辑、启停和删除，配置累计实付门槛、折扣、排序
- `src/views/marketing/points/`：积分规则配置；按会员、订单、类型和时间筛选积分流水
- `src/views/marketing/coupon/`：满减、折扣、兑换券配置；支持范围、兑换 SKU、库存限领、公开领取、定向发放和领取/使用记录
- `src/views/member/index.vue`：会员 360 增加等级、累计实付和积分入口
- `src/views/order/index.vue`：订单详情增加等级折扣、券优惠和积分抵扣拆分
- 菜单与权限由服务端 `sql/mysql/menu_marketing.sql` 动态下发，授权 ROOT + ADMIN
- 验证：`pnpm type-check`、`pnpm build` 及提交钩子 ESLint/Prettier/Stylelint 均通过
- 小程序未修改，后续直接接入已完成的 C 端营销与订单试算接口

### 阶段 6：最简预约管理页面（已完成）

- `src/api/appointment/`：预约分页接口与类型
- `src/views/appointment/index.vue`：预约记录只读列表，支持会员昵称/手机号和预约日期筛选
- 菜单与权限由服务端 `sql/mysql/menu_appointment.sql` 动态下发，授权 ROOT + ADMIN
- 不包含医生、排班、名额、SKU/订单关联、改期、取消、状态和通知
- 验证：`pnpm type-check`、`pnpm build` 及本地页面分页/筛选通过

### 阶段 7：页面装修 + 拼团

- `src/views/decoration/banner/`：Banner 管理（图片、跳转链接、排序）
- `src/views/decoration/notice/`：公告管理
- `src/views/decoration/brand/`：品牌背书内容编辑（富文本）
- `src/views/marketing/groupbuy/`：拼团活动管理（活动配置、成团要求、拼团订单查看）

### 阶段 8：分销 + 数据统计

- `src/views/distribution/agent/`：代理商管理（新增/审核/等级与佣金比例调整）
- `src/views/distribution/team/`：团队层级树
- `src/views/distribution/settlement/`：结算管理、提现审核（同意/拒绝/批量）
- `src/views/stats/`：数据统计（echarts：销售统计、订单统计、用户消费排行；对账单导出）

### 阶段 9：联调与部署

- 全模块权限点核对（按钮级权限走模板 `hasPerm` 指令体系）
- 生产构建 `pnpm build`、部署（可复用 `deploy.mjs`）

## 三、开发约定

- 新页面一律先用后端 codegen 生成基础 CRUD 再改，不从零手写
- 类型定义与后端 DTO 字段保持一致，统一放 `types.ts`
- 金额展示统一用分转元工具函数；时间统一 `YYYY-MM-DD HH:mm:ss`
- 每阶段完成标志：页面可用 + 权限点配置完成 + 用真实数据录入一遍
